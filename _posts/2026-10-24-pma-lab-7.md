## Lab 7-1

### Q1
>How does this program ensure that it continues running (achieves per-sistence) when the computer is restarted?

If we analyze it, at address `004010BC`, we will find the `CreateServiceA` API. This function registers a new service in the Windows Registry pointing to the current file path, and names it `MalService`. The value of `dwStartType` is set to `2` `SERVICE_AUTO_START`, which means the Service Control Manager (SCM) will automatically execute this malware every time the machine is restarted, successfully achieving persistence.

![](/assets/img/malware-analysis/Pasted%20image%2020260717002001.png)

Later, the code attempts to formally run as this service by registering the payload function `sub_401040` with the SCM using `StartServiceCtrlDispatcherA`

![](/assets/img/malware-analysis/Pasted%20image%2020260717001511.png)


![](/assets/img/malware-analysis/Pasted%20image%2020260717010206.png)

### Q2
>Why does this program use a mutex?

The program utilizes a synchronization object to ensure only a single instance runs on the machine. It checks for the existence of a specific mutex named `HGL345`. If this mutex is found, indicating the program is already active, it immediately calls `ExitProcess` to terminate. If the mutex is not found, the program creates it using `CreateMutexA` and proceeds with its execution.

![](/assets/img/malware-analysis/Pasted%20image%2020260717002857.png)

### Q3
>What is a good host-based signature to use for detecting this program?

- **Mutex Name:** `HGL345`, which can be detected using `process explorer` in dynamic analysis
- **Service Name:** `MalService` (configured as Auto-Start), This can be detected using the **Registry Key:** `HKLM\SYSTEM\CurrentControlSet\Services\MalService`

### Q4
>What is a good network-based signature for detecting this malware?

The `StartAddress` function, which is called by the `CreateThread` API at address `0040112C`, means the thread will execute from here. The function at `0040112C` uses network APIs to connect to the URL `http://www.malwareanalysisbook.com`, but we noticed it jumps to `loc_40116D` in an infinite loop.

![](/assets/img/malware-analysis/Pasted%20image%2020260717003947.png)

### Q5
>What is the purpose of this program?

It creates a mutex named `HGL345` to make sure only one copy is running, installs itself as a Windows service named `MalService` for persistence, then creates a waitable timer set for the year `2100`, causing it to remain inactive (sleep) until that time.

![](/assets/img/malware-analysis/Pasted%20image%2020260803190900.png)

If the timer were ever triggered, it would create multiple threads `'20'` and then continue running indefinitely.

![](/assets/img/malware-analysis/Pasted%20image%2020260803191013.png)
### Q6
>When will this program finish executing?

The program will never finish executing naturally, as it enters an infinite loop.

![](/assets/img/malware-analysis/Pasted%20image%2020260802124317.png)

## Lab 7-2

### Q1
>How does this program achieve persistence?

The program does not achieve persistence. No persistence mechanism is implemented.

### Q2
> What is the purpose of this program?

![](/assets/img/malware-analysis/Pasted%20image%2020260719181129.png)

If we search for the value of CLSID in regedit:

![](/assets/img/malware-analysis/Pasted%20image%2020260719181014.png)

And the value of IID:

![](/assets/img/malware-analysis/Pasted%20image%2020260719181609.png)

The program creates an `IWebBrowser2` COM object using `CoCreateInstance()`. It then calls the method located at offset `0x2C` in the `IWebBrowser2` vtable. According to the `IWebBrowser2` interface definition, offset `0x2C` corresponds to the `Navigate()` method. The URL `http://www.malwareanalysisbook.com/ad.html` is passed as the first argument, confirming that the program instructs Internet Explorer to navigate to that webpage.

![](/assets/img/malware-analysis/Pasted%20image%2020260719235325.png)

### Q3
>When will this program finish executing?

The program finishes executing after calling `OleUninitialize()` and returning from `main`. It does not wait for Internet Explorer to finish loading the webpage. After invoking `Navigate()`, it releases its COM resources with `OleUninitialize()` and exits, while the Internet Explorer COM server may continue running independently after the client program terminates.

## Lab 7-3

### Q1
>How does this program achieve persistence to ensure that it continues running when the computer is restarted?

It replaces the `kernel32.dll` import with `kerne132.dll` in the Import Table of `.exe` files. As a result, the malicious DLL is loaded every time an infected executable is run, allowing the DLL to be loaded every time an infected executable is launched, including after a system reboot.


![](/assets/img/malware-analysis/Pasted%20image%2020260803204053.png)

### Q2
>What are two good host-based signatures for this malware?

In the file `Lab07-03.exe` there is a good host-based signature, which is the copying of the dll file to the new file `C:\\windows\\system32\\kerne132.dll`

![](/assets/img/malware-analysis/Pasted%20image%2020260803175831.png)

Another one is in the file `Lab07-03.dll`, which is the mutex name `SADFHUHF`

![](/assets/img/malware-analysis/Pasted%20image%2020260803180308.png)

### Q3
>What is the purpose of this program?

The program copies the file `Lab07-03.dll` to `C:\\windows\\system32\\kerne132.dll`.

It recursively scans directories starting from the path `"C:\\"`, identifies `.exe` files, and passes each executable's full path to `sub_4010A0` for processing.

![](/assets/img/malware-analysis/Pasted%20image%2020260804070917.png)

It searches the PE Import Table for the `kernel32.dll` import descriptor. Once found it overwrites its name with `kerne132.dll`, which is the second file with the Lab.

![](/assets/img/malware-analysis/Pasted%20image%2020260804085430.png)

If we analyzed the file `Lab07-03.dll`, it establishes a TCP connection to the hardcoded IP `127.26.152.13` on port `80`, where it waits for commands from the remote server and executes them using `CreateProcessA`.

### Q4
>How could you remove this malware once it is installed?

Remove the malicious `kerne132.dll`, restore or replace all patched executables (changing their import back to `kernel32.dll`), and terminate any infected processes before cleaning the files.
