When execution reaches the `ret` instruction, the value in `eax` matches the input.

![](/assets/img/reverse-engineering/assembly/Pasted%20image%2020260708203458.png)

![](/assets/img/reverse-engineering/assembly/Pasted%20image%2020260708203531.png)

Execution then returns to the previous return address that was pushed onto the stack.

![](/assets/img/reverse-engineering/assembly/Pasted%20image%2020260708203650.png)

The function then adds the last midpoint to the return value.

![](/assets/img/reverse-engineering/assembly/phase_4_test.gif)

For input `5`, the function adds the midpoints `7` and `3` to `5`, producing `15` (`0xF`).

The function adds the sum of midpoints to your input.

The code calculates the midpoint with this equation:

```c
cmp = ((arg3 - arg2) / 2) + arg2;
```

This is equivalent to the following midpoint formula:

```c
(arg3 + arg2) / 2
```

First midpoint: `(0 + 14) / 2 = 7`

Second midpoint: `(0 + 7) / 2 = 3`

Third midpoint: `(3 + 7) / 2 = 5`

We reached `5`, so the function returns `5 + 3 + 7 = 0xF`.

To get the value `10`, enter `3`, because `7 + 3 = 10`.

### Alternative solution

I also traced the program and wrote this Python brute-force script:

```python
def phase_4():
	if (myInput > 0) and (myInput <= 14):
		x = func_4(myInput, 0, 14)
		if (x == 10):
			print(f"win , input = {myInput}")
		else:
			print(f"fail , input = {myInput}")

def func_4(myInput, num2, num3):
	cmp = num2 + ((num3 - num2) >> 1)	# 7

	if (cmp <= myInput):

		if (cmp >= myInput):
			return cmp

		return (cmp + func_4(myInput, cmp+1, num3))

	else:

		return (cmp + func_4(myInput, num2, cmp-1))

for i in range(14):
	myInput = i+1
	phase_4()

```

![](/assets/img/reverse-engineering/assembly/Pasted%20image%2020260709232335.png)

We need to loop 15 times and reach `15` in the final iteration. The operation is:

`first = arr[first]`

At address `00007FF73207F1D0` on the stack, I found the array. The following screenshot shows it interpreted as unsigned long values:

![](/assets/img/reverse-engineering/assembly/Pasted%20image%2020260709232636.png)

So, the first number is `5`.

Set a breakpoint at `00007FF732072530` to inspect the second number, which is stored in `[rbp+24]`. You can also calculate it by summing the values yourself. Do not add the initial `5`: `[rbp+24]` starts at `0`, so summing from the second element gives `115`.

### Block 4

Before the loop, `[rbp+8]` contains the address of node1, and `[rbp+28]` now also contains the address of node1.

![](/assets/img/reverse-engineering/assembly/Pasted%20image%2020260705225825.png)

This block compares the first dword of the current node with that of the next node. If the current value is greater than or equal to the next value, the bomb does not explode.

The nodes are rearranged according to the numbers we entered.

First, we need to determine the first dword value for every node. Then, arrange the inputs so that each selected node’s first dword is greater than or equal to the next node’s value.

![](/assets/img/reverse-engineering/assembly/Pasted%20image%2020260705230729.png)

Interpreting the values as 32-bit unsigned integers gives the following order:

![](/assets/img/reverse-engineering/assembly/Pasted%20image%2020260705230853.png)

The order is:

`node5 > node4 > node3 > node1 > node6 > node2`

Therefore, the input is `5 4 3 1 6 2`.
